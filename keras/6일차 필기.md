## 1. Verbose 옵션 (`verbose`)

`model.fit()` 및 `model.evaluate()` 시 학습/평가 과정의 출력을 제어하는 매개변수입니다.

```python
model.fit(x_train, y_train, epochs=100, batch_size=10, verbose=1)
```

### [ verbose 설정값 요약 ]
* **`0` (Silent 모드)**: 화면에 아무것도 출력하지 않음.
* **`1` (Default / 상세 모드)**: 진행 막대(Progress Bar)와 함께 에포크별 손실(loss), 검증 손실(val_loss), 진행 시간 등을 상세히 출력.
* **`2` (간결 모드)**: 진행 막대를 제외하고 에포크(epoch)당 1줄씩 결과만 출력.
* **`3` 이상**: 에포크 횟수만 간략히 출력.

> 💡 **Tip (성능 관점)**  
> 콘솔 화면에 로그를 계속해서 출력(I/O)하는 작업은 시스템 리소스(시간, GPU/CPU 성능)를 소모합니다. 학습 속도를 최대로 높이고 싶거나 연산에 집중할 때는 `verbose=0`으로 설정하는 것이 좋습니다.

## 2. Validation (검증 데이터) 분할과 필요성

### (1) 검증 데이터가 필요한 이유
* **Train 데이터만으로 학습할 경우**: 모델이 Train 데이터의 특성에 지나치게 적합(과적합)되어, Train Loss는 계속 낮아지지만 실제 새로운 데이터를 평가할 때 손실과 큰 괴리가 생깁니다.
* 따라서 **Train 데이터의 Loss만으로는 모델의 참된 성능을 신뢰할 수 없습니다.**
* 이에 따라 학습 중 모델의 일반화 성능을 중간 검증하기 위해 **Validation (검증) 데이터**를 별도로 분할합니다.

### (2) Validation 데이터의 특징과 주의점
* Validation 데이터는 가중치(\(W, b\))를 역전파(Backpropagation)로 직접 수정하는 훈련 과정에 사용되지 않습니다.
* 오직 매 에포크(Epoch) 끝에서 현재 모델의 성능(`val_loss`)을 평가하는 **감시용(Monitoring)**으로만 활용됩니다.
* **Q. fit 할 때 Validation 대신 Test 데이터를 넣으면 안 되나요?**
  * 사람이 `val_loss` 지표를 보고 하이퍼파라미터를 계속 수정/튜닝하다 보면, 모델 및 파라미터 조합이 `val_loss`에 과적합(Overfitting to Validation set)되는 현상이 발생합니다.
  * 따라서 최종 객관적인 평가를 위해 학습 및 검증에 전혀 관여하지 않은 **최종 Test 데이터**를 별도로 남겨두어야 합니다.

### (3) Validation 데이터 분할 방법 3가지

#### ① 수동으로 검증 데이터 직접 전달 (`validation_data`)
```python
x_train, x_test, y_train, y_test = train_test_split(x, y, test_size=0.2, random_state=42)
x_train, x_val, y_train, y_val = train_test_split(x_train, y_train, test_size=0.25, random_state=42)

model.fit(x_train, y_train, epochs=100, validation_data=(x_val, y_val))
```

#### ② 자동 비율 분할 (`validation_split`)
`fit()` 함수 내부에서 `x_train` 데이터의 일정 비율을 자동으로 떼어내어 검증 데이터로 사용합니다.
```python
model.fit(x_train, y_train, epochs=100, validation_split=0.2) # 훈련 데이터의 20%를 검증용으로 사용
```

## 3. 학습 시간 측정 (`import time`)

학습에 소요되는 실행 시간을 측정하여 모델의 효율성을 평가할 수 있습니다.

```python
import time

start_time = time.time() # 현재 시스템 시간(초) 기록

model.fit(x_train, y_train, epochs=100, batch_size=32, verbose=0, validation_split=0.2)

end_time = time.time() # 학습 완료 후 시간 기록

print("걸린 시간 : ", round(end_time - start_time, 2), "초") # round(x, 2)로 소수점 2자리 반올림
```

## 4. 과적합 (Overfitting) 이해 및 History 시각화

### (1) 과적합(Overfitting)의 정의
* **Training Loss**는 계속 줄어드는데, **Validation Loss**는 감소하다가 일정 시점 이후 **다시 증가(상승)**하기 시작하는 현상입니다.
* 모델이 훈련 데이터의 노이즈까지 과도하게 암기하여 새로운 데이터에 대한 대응력(일반화 성능)이 떨어지는 구간입니다.

### (2) `hist = model.fit()` 및 `hist.history` 반환값 활용
`model.fit()` 결과는 `History` 객체를 반환합니다.
```python
hist = model.fit(x_train, y_train, epochs=100, batch_size=32, validation_split=0.2)

print(hist.history) 
# 반환 형태: {'loss': [0.5, 0.4, ...], 'val_loss': [0.6, 0.45, ...]}
```

### (3) Matplotlib을 활용한 Loss 곡선 시각화
초기 Epoch의 매우 높은 손실값 때문에 그래프 축이 왜곡되는 것을 방지하기 위해 슬라이싱(`[2:]` 등)을 활용하여 시각화합니다.

```python
import matplotlib.pyplot as plt

plt.figure(figsize=(9, 6)) # 캔버스 크기 설정
plt.rcParams['font.family'] = 'Malgun Gothic' # 한글 폰트 설정 (맑은 고딕)
plt.rcParams['axes.unicode_minus'] = False # 마이너스 기호 깨짐 방지

# 3번째 Epoch부터 시각화 (초기 손실값 제외)
plt.plot(hist.history['loss'][2:], c='red', label='loss')
plt.plot(hist.history['val_loss'][2:], c='blue', label='val_loss')

plt.legend(loc='upper right') # 우측 상단 범례 표시
plt.title('Loss 및 Val_Loss 과적합 그래프')
plt.xlabel('Epoch')
plt.ylabel('Loss')
plt.grid()
plt.show()
```

## 5. 조기 종료 (Early Stopping)

과적합이 시작되거나 더 이상 검증 성능이 향상되지 않을 때, 지정한 Epoch까지 기다리지 않고 학습을 자동으로 중단시키는 Callback 기능입니다.

```python
from tensorflow.keras.callbacks import EarlyStopping

es = EarlyStopping(
    monitor='val_loss',        # 감시할 지표 (검증 손실)
    mode='min',                # 지표 판단 기준 ('min': 작을수록 좋음, 'max': 클수록 좋음, 'auto': 자동)
    patience=10,               # val_loss가 개선되지 않더라도 참아줄 Epoch 횟수
    restore_best_weights=True  # 학습 종료 시 가장 val_loss가 우수했던 시점의 최적 가중치(W, b)로 복원
)

model.fit(
    x_train, y_train,
    epochs=1000,
    batch_size=32,
    validation_split=0.2,
    callbacks=[es] # EarlyStopping 콜백 등록
)
```

### [ EarlyStopping 주요 파라미터 상세 ]
1. **`monitor`**: 어떤 지표를 감시할지 설정 (`'val_loss'`, `'val_accuracy'` 등).
2. **`mode`**: 
   * `'min'`: `loss`, `val_loss` 등 값이 작아져야 좋은 지표일 때 사용.
   * `'max'`: `accuracy`, `R2` 등 값이 커져야 좋은 지표일 때 사용.
   * `'auto'`: 케라스가 지표명을 보고 자동판단.
3. **`patience`**: 연속해서 설정한 횟수(Epoch)만큼 성능 개선이 없으면 학습을 중단함.
4. **`restore_best_weights`**:
   * `False` (기본값): 조기 중단된 마지막 Epoch의 가중치 사용.
   * **`True` (권장)**: 중단 시점이 아닌, `val_loss`가 **가장 최적(최소)이었던 Epoch의 가중치(W, b)로 되돌림**.
