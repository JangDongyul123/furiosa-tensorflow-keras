# Functional API, Dropout, Branch 모델과 앙상블 정리

## 1. 전체 핵심 요약

이번 내용을 한 번에 정리하면 다음과 같다.

```text
Sequential
= 레이어를 일렬로 쌓는 방식

Functional API
= 레이어의 연결 구조를 직접 설계하는 방식

Dropout
= 학습 중 일부 뉴런의 출력을 랜덤하게 0으로 만들어 과적합을 줄이는 방법

앙상블
= 여러 모델을 독립적으로 학습한 뒤 결과를 결합

Branch 모델
= 하나의 모델 안에서 여러 경로를 만들고,
  하나의 최종 Loss를 기준으로 함께 학습
```

특히 중요한 점은 다음과 같다.

> **Functional API는 성능을 자동으로 높여주는 것이 아니라, 복잡한 신경망 구조를 만들 수 있게 해주는 방법이다.**

> **Dropout은 가중치 자체를 삭제하는 것이 아니라, 학습 중 일부 뉴런의 출력을 일시적으로 0으로 만든다.**

> **앙상블은 각 모델이 독립적으로 학습하지만, Branch 모델은 하나의 최종 Loss를 공유하며 공동으로 학습한다.**

---

# 2. Sequential 모델

Sequential 모델은 레이어를 순서대로 쌓는 방식이다.

```python
model = Sequential()

model.add(Dense(500, activation='relu'))
model.add(Dense(250, activation='relu'))
model.add(Dense(125, activation='relu'))
model.add(Dense(7, activation='softmax'))
```

구조는 다음과 같다.

```text
Input
  ↓
Dense
  ↓
Dense
  ↓
Dense
  ↓
Output
```

즉 기본적으로

```text
A → B → C → D
```

형태의 일직선 구조를 표현하기에 적합하다.

---

# 3. Functional 모델

Functional API에서는 각 레이어의 입력과 출력을 직접 연결한다.

```python
input1 = Input(shape=(10,))

dense1 = Dense(500, activation='relu')(input1)
dense2 = Dense(250, activation='relu')(dense1)
dense3 = Dense(125, activation='relu')(dense2)

output1 = Dense(7, activation='softmax')(dense3)

model = Model(
    inputs=input1,
    outputs=output1
)
```

이 코드도 실제 구조는

```text
Input
  ↓
Dense
  ↓
Dense
  ↓
Dense
  ↓
Output
```

이므로 같은 구조의 Sequential 모델과 계산상 거의 동일하다.

즉,

```text
Sequential이라 성능이 낮고
Functional이라 성능이 높은 것
```

은 아니다.

같은 레이어를 같은 방식으로 연결했다면 모델 구조 자체는 같다.

---

# 4. Functional API의 장점

Functional API의 장점은 **복잡한 연결 구조를 자유롭게 설계할 수 있다는 점**이다.

Sequential은 기본적으로

```text
A → B → C → D
```

같은 일렬 구조에 적합하지만, Functional API에서는 다음과 같은 구조를 만들 수 있다.

---

## 4-1. 하나의 입력을 여러 Branch로 나누기

```text
              → Branch A →
Input ───────               → Merge → Output
              → Branch B →
```

예를 들어 같은 입력을 두 경로에서 서로 다른 방식으로 처리할 수 있다.

```python
input1 = Input(shape=(100,))

branch_a = Dense(64, activation='relu')(input1)
branch_a = Dense(32, activation='relu')(branch_a)

branch_b = Dense(128, activation='relu')(input1)
branch_b = Dense(32, activation='relu')(branch_b)
```

두 Branch는 서로 다른 가중치를 가지므로 같은 입력을 보더라도 서로 다른 표현을 학습할 수 있다.

---

## 4-2. 왜 여러 갈래로 나누는가?

가장 큰 이유는 **같은 입력을 여러 관점에서 처리하기 위해서**이다.

예를 들어 입력 feature가 다음과 같다고 하자.

```text
키
몸무게
나이
연봉
운동시간
수면시간
```

하나의 경로만 사용하면 모든 feature를 하나의 흐름에서 처리한다.

```text
Input → Dense → Dense → Output
```

반면 여러 Branch를 만들면

```text
              → Branch A →
Input ───────               → Merge → Output
              → Branch B →
```

각 Branch가 서로 다른 가중치를 가지므로 학습 과정에서 서로 다른 특징을 잘 표현하는 방향으로 발전할 수 있다.

예를 들어 결과적으로

```text
Branch A
→ 신체 관련 패턴에 강한 표현

Branch B
→ 생활습관이나 소득 관련 패턴에 강한 표현
```

처럼 서로 다른 역할을 맡을 가능성이 생긴다.

단, 이것이 자동으로 보장되는 것은 아니다.

단순히 Branch를 많이 만든다고 반드시 성능이 좋아지는 것도 아니다.

---

## 4-3. 여러 입력을 받을 수 있다

Functional 모델에서는 입력 자체를 여러 개 사용할 수 있다.

```text
이미지 ─────→ CNN ───────┐
                         │
수치 데이터 → Dense ─────┼→ Merge → Output
                         │
텍스트 ─────→ Encoder ───┘
```

예를 들어 집값 예측 문제라면

```text
집 사진
집 면적
방 개수
지역 정보
```

를 서로 다른 방식으로 처리한 뒤 합칠 수 있다.

---

## 4-4. 여러 출력을 만들 수 있다

하나의 모델에서 여러 출력을 동시에 만들 수도 있다.

```text
               → Output A
              /
Hidden Layer
              \
               → Output B
```

예를 들어 하나의 이미지를 입력받아

```text
출력 1 → 객체 종류
출력 2 → 객체 위치
출력 3 → 객체 크기
```

처럼 여러 작업을 동시에 수행할 수 있다.

---

## 4-5. Skip Connection을 만들 수 있다

Functional API에서는 중간 레이어를 건너뛰는 연결도 만들 수 있다.

```text
Input ─→ Dense ─→ Dense ─→ (+) → Output
  │                       ↑
  └───────────────────────┘
```

이런 구조는 ResNet의 핵심 아이디어인 Residual Connection과 연결된다.

Sequential 모델에서는 이런 구조를 표현하기 어렵다.

---

# 5. Functional 모델이라고 Dense 연결이 줄어드는 것은 아니다

Functional API를 사용한다고 해서 Dense 레이어의 연결이 자동으로 줄어드는 것은 아니다.

예를 들어

```python
dense1 = Dense(500)(input1)
dense2 = Dense(500)(dense1)
```

이라면 첫 번째 Dense의 500개 뉴런과 두 번째 Dense의 500개 뉴런은 기본적으로 모두 연결된다.

즉 대략

```text
500 × 500 = 250,000개
```

의 연결 가중치가 존재한다.

Functional API는

```text
연결을 적게 만드는 기술
```

이 아니라

```text
연결 구조를 자유롭게 설계하는 방법
```

이다.

---

# 6. Dropout

Dropout은 과적합을 줄이기 위한 정규화 기법이다.

예를 들어 다음과 같은 모델이 있다고 하자.

```python
model.add(Dense(500, activation='relu'))
model.add(Dropout(0.2))
model.add(Dense(250, activation='relu'))
```

`Dropout(0.2)`는 학습 중 앞 레이어의 출력 뉴런 중 약 20%를 랜덤하게 비활성화한다.

---

# 7. Dropout은 가중치 W를 삭제하는 것이 아니다

이 부분이 중요하다.

예를 들어 어떤 뉴런의 출력값이

```text
h1 = 5
```

라고 하자.

Dropout에 선택되면 학습 중에는

```text
h1 = 0
```

처럼 처리된다.

따라서 다음 레이어에서

```text
h1 × w
```

는

```text
0 × w = 0
```

이 된다.

즉 그 뉴런과 연결된 경로가 이번 학습에서는 사실상 사용되지 않는다.

하지만 가중치 자체가 삭제되는 것은 아니다.

```text
Dropout
≠ W 삭제

Dropout
= 일부 뉴런의 출력값을 일시적으로 0으로 만듦
```

---

# 8. Dropout은 학습할 때 활성화 조합을 계속 바꾼다

예를 들어 뉴런이 4개 있다고 하자.

```text
h1
h2
h3
h4
```

`Dropout(0.5)`를 사용하면 학습 중 약 절반이 랜덤하게 꺼진다.

첫 번째 학습 step에서는

```text
h1 → ON
h2 → OFF
h3 → ON
h4 → OFF
```

일 수 있다.

다음 학습 step에서는

```text
h1 → OFF
h2 → ON
h3 → OFF
h4 → ON
```

처럼 달라질 수 있다.

또 다음에는

```text
h1 → ON
h2 → ON
h3 → OFF
h4 → OFF
```

가 될 수도 있다.

즉 학습 과정에서 뉴런의 활성화 조합이 계속 바뀐다.

---

# 9. Dropout 조합은 Epoch마다 한 번만 바뀌는 것이 아니다

Dropout은 보통 epoch마다 한 번만 바뀌는 것이 아니라, **학습 step마다 새로운 Dropout mask가 적용된다.**

일반적인 `model.fit()`에서는 batch 단위로 학습 step이 진행되므로 직관적으로 다음처럼 이해할 수 있다.

```text
Epoch 1

Batch 1
→ Dropout 조합 A

Batch 2
→ Dropout 조합 B

Batch 3
→ Dropout 조합 C

...

Epoch 2

Batch 1
→ 또 새로운 조합
```

즉 Dropout은 학습 과정에서 매우 자주 다른 부분 신경망을 사용하게 만든다.

---

# 10. Dropout이 과적합을 줄이는 이유

Dropout이 없으면 특정 뉴런들이 서로 지나치게 의존할 수 있다.

예를 들어

```text
뉴런 A가 항상 뉴런 B의 출력을 믿는 구조
```

가 만들어질 수 있다.

하지만 Dropout을 사용하면 뉴런 B가 언제든 꺼질 수 있다.

```text
A → ON
B → OFF
C → ON
```

따라서 A는 B 하나에만 의존할 수 없다.

다른 뉴런이나 다른 특징도 활용해야 한다.

그 결과 특정 학습 데이터에 지나치게 맞춰지는 현상을 줄일 수 있다.

---

# 11. Dropout의 또 다른 직관

Dropout은 하나의 큰 신경망에서 매 학습 step마다 서로 다른 작은 부분 신경망을 학습시키는 것처럼 볼 수도 있다.

```text
전체 신경망

   ↓

부분 신경망 A
부분 신경망 B
부분 신경망 C
부분 신경망 D
...
```

따라서 특정 하나의 경로에 지나치게 의존하는 것을 줄이는 효과가 있다.

---

# 12. Functional Branch와 Dropout의 차이

둘은 완전히 다른 개념이다.

## Functional Branch

```text
여러 경로를 의도적으로 만든다.
```

예:

```text
              → Branch A →
Input ───────               → Merge
              → Branch B →
```

두 Branch는 학습 중 계속 존재한다.

---

## Dropout

```text
이미 존재하는 경로 중 일부를
학습할 때마다 랜덤하게 비활성화한다.
```

예:

```text
이번 Batch
h1 ON
h2 OFF
h3 ON

다음 Batch
h1 OFF
h2 ON
h3 ON
```

따라서

```text
Functional Branch
= 여러 경로를 설계

Dropout
= 기존 경로를 랜덤하게 일부 끄기
```

이다.

---

# 13. Branch 모델은 앙상블과 비슷해 보인다

다음 구조를 보면

```text
              Branch A ─┐
Input ───────            ├→ Merge → Output
              Branch B ─┘
```

겉으로는 여러 모델의 결과를 합치는 앙상블과 비슷하다.

앙상블도 보통 다음과 같은 구조를 가진다.

```text
Model A ─┐
Model B ─┼→ 평균 / 투표 → 최종 예측
Model C ─┘
```

따라서 Branch 모델은

> **앙상블과 비슷한 다중 경로 구조를 하나의 모델 내부에서 구현한 것처럼 볼 수 있다.**

하지만 학습 방식에는 중요한 차이가 있다.

---

# 14. 독립 앙상블 모델

앙상블에서는 각 모델을 보통 독립적으로 학습한다.

```text
Model A → y_hat_A → Loss_A
Model B → y_hat_B → Loss_B
Model C → y_hat_C → Loss_C
```

각 모델은 자신의 Loss만 보고 자신의 가중치를 업데이트한다.

```text
Loss_A → Model A의 W 업데이트
Loss_B → Model B의 W 업데이트
Loss_C → Model C의 W 업데이트
```

즉 Model A는 Model B가 무엇을 예측하는지 알 필요가 없다.

각자 정답을 잘 맞히는 것이 목표이다.

---

# 15. Branch 모델은 하나의 최종 Loss를 공유한다

Functional Branch 모델은 다르다.

```text
Branch A ─┐
          ├→ Merge → 최종 예측 → Loss
Branch B ─┘
```

두 Branch는 각각 다른 가중치를 가진다.

```text
Branch A → W_A
Branch B → W_B
```

그러나 최종 Loss는 하나다.

이 Loss가 역전파되면서 두 Branch의 가중치가 동시에 업데이트된다.

```text
              Loss
               ↓
            역전파
          ↙         ↘
     Branch A      Branch B
       W_A           W_B
```

즉 두 Branch는 가중치를 직접 공유하는 것이 아니라

> **하나의 최종 Loss를 공유하면서 공동으로 학습한다.**

이를 `Joint Training`이라고 볼 수 있다.

---

# 16. Branch는 서로를 간접적으로 의식한다

예를 들어 정답이 다음과 같다고 하자.

```text
y = 10
```

Branch 두 개의 예측이

```text
Branch A = 8
Branch B = 12
```

라고 하자.

두 결과를 평균내면

```text
(8 + 12) / 2 = 10
```

이다.

따라서 최종 모델의 예측은 정답과 같다.

```text
Branch A = 8  ─┐
               ├→ 평균 = 10 → Loss ≈ 0
Branch B = 12 ─┘
```

Branch A 혼자 보면 틀렸고 Branch B 혼자 봐도 틀렸다.

하지만 두 Branch의 조합은 맞았다.

따라서 Branch 모델에서는

```text
A 혼자 정답을 맞혀야 한다.
B 혼자 정답을 맞혀야 한다.
```

가 아니라

```text
A와 B를 합친 최종 결과가 정답을 잘 맞히면 된다.
```

라는 방향으로 학습될 수 있다.

즉 각 Branch가 서로 부족한 부분을 보완할 수 있다.

---

# 17. 독립 앙상블은 서로를 의식하지 않는다

같은 예시를 독립 앙상블에서 보면 다르다.

```text
정답 = 10

Model A = 8
Model B = 12
```

각 모델은 자신의 Loss를 따로 계산한다.

```text
Model A
8 → 정답 10과 비교 → Loss_A

Model B
12 → 정답 10과 비교 → Loss_B
```

따라서 두 모델 모두 각각 `10`에 가까워지도록 학습한다.

학습이 끝난 뒤에야 결과를 합친다.

```text
Model A ─┐
         ├→ 평균 → 최종 예측
Model B ─┘
```

즉

> **앙상블은 각자가 잘한 뒤 합친다.**

라고 이해할 수 있다.

---

# 18. Branch 모델은 함께 잘하도록 학습한다

Branch 모델에서는 처음부터 하나의 최종 Loss가 존재한다.

```text
Branch A ─┐
          ├→ 최종 예측 → Loss
Branch B ─┘
```

따라서

> **Branch 모델은 처음부터 함께 잘하도록 학습한다.**

라고 이해할 수 있다.

---

# 19. 수식으로 보는 차이

## 독립 앙상블

두 모델이 있다면 각각

```text
Loss_A = L(y, y_hat_A)

Loss_B = L(y, y_hat_B)
```

를 최소화한다.

따라서 각각의 모델이 정답에 가까워지는 것이 목표다.

---

## Branch 모델

Branch 결과의 평균을 최종 예측으로 사용한다면

```text
y_hat = (y_hat_A + y_hat_B) / 2
```

이고 최종 Loss는

```text
Loss = L(y, (y_hat_A + y_hat_B) / 2)
```

가 된다.

따라서 각 Branch가 개별적으로 정답일 필요는 없다.

둘의 조합이 정답에 가까우면 된다.

---

# 20. 가중치를 공유한다는 표현은 정확하지 않다

Branch 모델에서

```text
Branch A → W_A
Branch B → W_B
```

는 각각 서로 다른 가중치이다.

따라서

```text
Branch A의 W가
Branch B에게 직접 전달된다.
```

라는 의미는 아니다.

정확한 표현은 다음과 같다.

> **가중치 자체를 공유하는 것이 아니라, 하나의 최종 Loss를 공유하면서 공동으로 최적화된다.**

즉

```text
Weight Sharing
```

이라기보다는

```text
Joint Training
```

에 가깝다.

# 21. 앙상블과 Branch 모델의 비유

## 앙상블

학생 여러 명이 각자 혼자 공부한다.

```text
학생 A → 혼자 공부
학생 B → 혼자 공부
학생 C → 혼자 공부
```

각자 시험을 본 뒤 마지막에 답을 모아 평균이나 투표를 한다.

```text
A의 답
B의 답
C의 답

   ↓

평균 / 투표
```

각 학생은 다른 학생을 의식할 필요가 없다.

---

## Branch 모델

학생 여러 명이 처음부터 하나의 팀으로 공동 답안을 만든다.

```text
학생 A ─┐
학생 B ─┼→ 하나의 공동 답안
학생 C ─┘
```

평가는 개인 점수가 아니라 팀 전체 답안의 점수다.

따라서

```text
A가 부족한 부분을 B가 보완하고
B가 부족한 부분을 C가 보완
```

하는 식의 역할 분담이 가능하다.

---

# 22. 왜 두 방식의 성능이 다를 수 있는가?

학습 목표가 다르기 때문이다.

## 앙상블

```text
각 모델이 혼자서 정답을 잘 맞히도록 학습
```

따라서 여러 독립적인 모델이 서로 다른 실수를 할 수 있고, 그 실수를 평균이나 투표로 상쇄할 수 있다.

---

## Branch 모델

```text
여러 Branch의 조합이 정답을 잘 맞히도록 학습
```

따라서 Branch가 서로 보완하는 표현을 학습할 수 있다.

하지만 같은 Loss를 보며 함께 학습하기 때문에 서로 비슷한 방향으로 움직일 수도 있다.

즉

```text
Branch를 많이 만든다고
항상 앙상블보다 좋은 것은 아니다.
```

# 23. 세 개념 비교

| 구분 | Functional Branch | Dropout | 독립 앙상블 |
|---|---|---|---|
| 목적 | 복잡한 구조 설계, 여러 표현 결합 | 과적합 감소 | 일반화 성능 및 안정성 향상 |
| 경로 | 여러 경로를 명시적으로 생성 | 기존 경로 일부를 랜덤 비활성화 | 모델 자체를 여러 개 생성 |
| 학습 | 하나의 모델로 공동 학습 | 하나의 모델 내부에서 랜덤하게 일부 제거 | 각 모델을 독립적으로 학습 |
| Loss | 보통 하나의 최종 Loss 공유 | 원래 모델의 Loss 사용 | 모델마다 개별 Loss |
| 가중치 | Branch별로 별도 가중치 | 가중치는 유지됨 | 모델마다 별도 가중치 |
| 결과 결합 | 모델 내부에서 결합 | 별도 결합 없음 | 학습 후 평균/투표 등으로 결합 |

# 24. 최종 핵심 정리

```text
Functional API
= 레이어 연결 구조를 자유롭게 설계하는 방법

Branch
= 하나의 모델 안에 여러 경로를 만드는 것

Dropout
= 학습 중 일부 뉴런 출력을 랜덤하게 0으로 만들어
  특정 뉴런에 지나치게 의존하는 것을 줄이는 방법

앙상블
= 여러 모델을 독립적으로 학습한 후 결과를 결합

Branch 모델
= 여러 경로가 하나의 최종 Loss를 공유하며 함께 학습
```

가장 중요한 문장을 다시 정리하면 다음과 같다.

> **Functional API는 성능 향상 기법 자체라기보다 복잡한 모델 구조를 만들기 위한 도구이다.**

> **Dropout은 가중치를 지우는 것이 아니라 학습 중 일부 뉴런의 출력을 랜덤하게 끄며, 학습 step마다 다른 부분 신경망을 사용하는 효과를 만든다.**

> **앙상블은 각 모델이 서로를 의식하지 않고 독립적으로 학습한 뒤 결과를 합친다.**

> **Branch 모델은 각 Branch의 가중치는 따로 가지지만 하나의 최종 Loss를 공유하므로, 서로의 결과를 간접적으로 의식하면서 함께 가중치가 업데이트된다.**

한 문장으로 줄이면:

> **앙상블은 "각자 잘한 뒤 합치는 방식"이고, Branch 모델은 "처음부터 함께 잘하도록 학습하는 방식"이다.**
