# 11일차 필기

## 1. Functional 모델, Dropout, Branch 모델과 앙상블 핵심 요약

```text
Sequential
= 레이어를 일렬로 쌓는 방식

Functional 모델
= Input과 Model을 사용해 레이어의 연결 구조를 직접 설계한 모델

Dropout
= 학습 중 각 뉴런의 출력값을 일정 확률로 0으로 만들어
  특정 뉴런이나 경로에 지나치게 의존하는 것을 줄이는 방법

앙상블
= 여러 모델을 각각 학습한 뒤 결과를 결합하는 방법

Branch 모델
= 하나의 모델 안에서 여러 경로를 만들고,
  최종 출력의 Loss를 통해 함께 학습하는 구조
```

핵심:

> **Functional 모델은 Sequential보다 자동으로 성능이 좋아지는 모델이 아니라, 복잡한 연결 구조를 표현할 수 있도록 만든 모델이다.**

> **Dropout은 가중치 W를 삭제하는 것이 아니라 학습 중 일부 뉴런의 출력값을 확률적으로 0으로 만든다.**

> **독립 앙상블은 모델들이 따로 학습한 뒤 결과를 합치고, Branch 모델은 하나의 계산 그래프 안에서 최종 Loss를 통해 함께 학습한다.**

---

# 2. Sequential 모델

Sequential 모델은 레이어를 순서대로 쌓는 방식이다.

```python
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense

model = Sequential()

model.add(Dense(500, activation='relu'))
model.add(Dense(250, activation='relu'))
model.add(Dense(125, activation='relu'))
model.add(Dense(7, activation='softmax'))
```

구조:

```text
Input
  ↓
Dense
  ↓
Dense
  ↓
Dense
  ↓
Output
```

즉 기본적으로

```text
A → B → C → D
```

형태의 일직선 구조를 표현하기에 적합하다.

---

# 3. Functional 모델


### Functional 모델과 Functional API의 차이

```text
Functional 모델
= 실제로 만들어진 모델의 형태

Functional API
= Functional 모델을 만들 때 사용하는 Keras 작성 방식
```

예를 들어 다음 코드는 **Functional API를 사용해서 Functional 모델을 만든 것**이다.

```python
input1 = Input(shape=(10,))
x = Dense(64, activation='relu')(input1)
output = Dense(1)(x)

model = Model(inputs=input1, outputs=output)
```

따라서 이 필기에서는 모델 자체를 설명할 때는 **Functional 모델**이라고 부른다.

---


Functional 모델은 각 레이어의 입력과 출력을 직접 연결해서 만든다.

```python
from tensorflow.keras.layers import Input, Dense
from tensorflow.keras.models import Model

input1 = Input(shape=(10,))

dense1 = Dense(500, activation='relu')(input1)
dense2 = Dense(250, activation='relu')(dense1)
dense3 = Dense(125, activation='relu')(dense2)

output1 = Dense(7, activation='softmax')(dense3)

model = Model(
    inputs=input1,
    outputs=output1
)
```

이 코드의 구조도

```text
Input
  ↓
Dense
  ↓
Dense
  ↓
Dense
  ↓
Output
```

이므로 같은 구조의 Sequential 모델과 계산 구조는 사실상 같다.

따라서

```text
Sequential이라 성능이 낮고
Functional이라 성능이 높은 것
```

은 아니다.

같은 레이어를 같은 방식으로 연결했다면 모델 구조 자체는 같다.

---

# 4. Functional 모델의 장점

Functional 모델의 가장 큰 장점은 **복잡한 연결 구조를 자유롭게 설계할 수 있다는 점**이다.

Sequential은 기본적으로

```text
A → B → C → D
```

같은 일렬 구조에 적합하다.

Functional 모델에서는 다음과 같은 구조를 만들 수 있다.

---

## 4-1. 하나의 입력을 여러 Branch로 나누기

```text
              ┌→ Branch A ─┐
Input ────────┤             ├→ Merge → Output
              └→ Branch B ─┘
```

예:

```python
input1 = Input(shape=(100,))

branch_a = Dense(64, activation='relu')(input1)
branch_a = Dense(32, activation='relu')(branch_a)

branch_b = Dense(128, activation='relu')(input1)
branch_b = Dense(32, activation='relu')(branch_b)
```

두 Branch는 서로 다른 가중치를 가지므로 같은 입력을 보더라도 서로 다른 표현을 학습할 수 있다.

---

## 4-2. 왜 여러 Branch로 나누는가?

같은 입력을 여러 경로에서 서로 다른 방식으로 처리하기 위해서다.

예를 들어 입력 feature가 다음과 같다고 하자.

```text
키
몸무게
나이
연봉
운동시간
수면시간
```

하나의 경로만 사용하면:

```text
Input → Dense → Dense → Output
```

여러 Branch를 사용하면:

```text
              ┌→ Branch A ─┐
Input ────────┤             ├→ Merge → Output
              └→ Branch B ─┘
```

각 Branch가 서로 다른 가중치를 가지므로 서로 다른 특징을 표현하는 방향으로 학습될 수 있다.

예:

```text
Branch A
→ 신체 관련 패턴을 잘 표현

Branch B
→ 생활습관이나 소득 관련 패턴을 잘 표현
```

단, 이런 역할 분담이 자동으로 보장되는 것은 아니다.

Branch를 많이 만든다고 반드시 성능이 좋아지는 것도 아니다.

---

## 4-3. 여러 입력을 받을 수 있다

Functional 모델에서는 입력 자체를 여러 개 사용할 수 있다.

```text
이미지 ─────→ CNN ───────┐
                         │
수치 데이터 → Dense ─────┼→ Merge → Output
                         │
텍스트 ─────→ Encoder ───┘
```

예를 들어 집값 예측 문제라면

```text
집 사진
집 면적
방 개수
지역 정보
```

를 서로 다른 방식으로 처리한 뒤 합칠 수 있다.

---

## 4-4. 여러 출력을 만들 수 있다

하나의 모델에서 여러 출력을 동시에 만들 수도 있다.

```text
                   ┌→ Output A
Hidden Layer ──────┤
                   └→ Output B
```

예를 들어 하나의 이미지를 입력받아

```text
출력 1 → 객체 종류
출력 2 → 객체 위치
출력 3 → 객체 크기
```

처럼 여러 작업을 동시에 수행할 수 있다.

---

## 4-5. Skip Connection을 만들 수 있다

Functional 모델에서는 중간 레이어를 건너뛰는 연결도 만들 수 있다.

```text
Input ─→ Dense ─→ Dense ─→ (+) → Output
  │                         ↑
  └─────────────────────────┘
```

이런 구조는 ResNet의 핵심 아이디어인 Residual Connection과 연결된다.

Sequential 모델에서는 이런 구조를 표현하기 어렵다.

---

# 5. Functional 모델이라고 Dense 연결이 줄어드는 것은 아니다

Functional 모델을 사용한다고 해서 Dense 레이어의 연결 수가 자동으로 줄어드는 것은 아니다.

예:

```python
dense1 = Dense(500)(input1)
dense2 = Dense(500)(dense1)
```

첫 번째 Dense의 출력 뉴런 500개와 두 번째 Dense의 뉴런 500개가 모두 연결된다.

가중치 수:

```text
500 × 500 = 250,000개
```

bias까지 포함하면 두 번째 Dense의 파라미터 수는:

```text
500 × 500 + 500
= 250,500개
```

Functional 모델은

```text
연결을 적게 만드는 모델
```

이 아니라

```text
연결 구조를 자유롭게 설계한 모델
```

이다.

---

# 6. Dropout

Dropout은 과적합을 줄이기 위한 정규화 기법이다.

```python
from tensorflow.keras.layers import Dropout

model.add(Dense(500, activation='relu'))
model.add(Dropout(0.2))
model.add(Dense(250, activation='relu'))
```

`Dropout(0.2)`의 정확한 의미는:

> **학습 중 각 뉴런의 출력값이 20% 확률로 0이 된다.**

즉

```text
전체 뉴런 중 정확히 20%를 골라서 끈다
```

는 뜻이 아니다.

각 뉴런의 출력값마다 확률적으로 Dropout이 적용된다.

따라서 한 step에서 실제로 꺼지는 비율은 정확히 20%가 아닐 수 있다.

다만 많은 뉴런과 여러 학습 step을 기준으로 보면 평균적으로 약 20%가 꺼지는 효과가 난다.

---

# 7. Dropout은 W를 삭제하는 것이 아니다

예를 들어 어떤 뉴런의 출력값이:

```text
h1 = 5
```

라고 하자.

Dropout에 의해 이 뉴런의 출력이 꺼지면:

```text
h1 = 0
```

처럼 처리된다.

그러면 다음 레이어에서:

```text
h1 × w
```

는

```text
0 × w = 0
```

이 된다.

즉 그 뉴런을 통한 경로가 이번 학습 step에서는 사실상 사용되지 않는다.

하지만 가중치 자체가 삭제되는 것은 아니다.

```text
Dropout ≠ W 삭제

Dropout
= 일부 뉴런의 출력값을 일시적으로 0으로 만듦
```

---

# 8. `Dropout(0.5)`는 정확히 절반을 끄는 것이 아니다

뉴런 출력이 4개 있다고 하자.

```text
h1
h2
h3
h4
```

`Dropout(0.5)`는 각 출력값이 50% 확률로 0이 된다는 뜻이다.

예를 들어 어떤 학습 step에서는:

```text
h1 → ON
h2 → OFF
h3 → ON
h4 → OFF
```

다른 step에서는:

```text
h1 → OFF
h2 → OFF
h3 → OFF
h4 → ON
```

또 다른 step에서는:

```text
h1 → ON
h2 → ON
h3 → ON
h4 → OFF
```

가 될 수도 있다.

즉:

```text
Dropout(0.5)
= 각 출력이 50% 확률로 OFF

≠ 매번 전체 뉴런 중 정확히 절반을 뽑아서 OFF
```

이다.

---

# 9. Dropout mask는 학습 step마다 바뀐다

Dropout은 epoch마다 한 번만 바뀌는 것이 아니다.

일반적으로 **학습 step마다 새로운 Dropout mask가 적용된다.**

mini-batch 학습에서는 다음처럼 이해할 수 있다.

```text
Epoch 1

Batch 1
→ Dropout 조합 A

Batch 2
→ Dropout 조합 B

Batch 3
→ Dropout 조합 C

...

Epoch 2

Batch 1
→ 또 새로운 조합
```

즉 학습 과정에서 계속 다른 부분 신경망을 사용하는 효과가 생긴다.

---

# 10. Dropout이 과적합을 줄이는 이유

Dropout이 없으면 특정 뉴런들이 서로 지나치게 의존할 수 있다.

예:

```text
뉴런 A가 항상 뉴런 B의 출력에 의존
```

하지만 Dropout을 사용하면 B가 언제든 꺼질 수 있다.

```text
A → ON
B → OFF
C → ON
```

그러면 모델은 B 하나에만 의존할 수 없고 다른 뉴런이나 다른 특징도 활용해야 한다.

이 때문에 특정 학습 데이터나 특정 경로에 지나치게 맞춰지는 현상을 줄이는 데 도움이 된다.

---

# 11. Dropout의 또 다른 직관

Dropout은 하나의 큰 신경망에서 매 학습 step마다 서로 다른 작은 부분 신경망을 사용하는 것처럼 볼 수 있다.

```text
전체 신경망
   ↓
부분 신경망 A
부분 신경망 B
부분 신경망 C
부분 신경망 D
...
```

하지만 실제로 여러 모델을 따로 만드는 것은 아니다.

하나의 모델에서 랜덤 mask를 적용하는 것이다.

---

# 12. 학습과 추론에서 Dropout의 차이

학습 중:

```text
Dropout 활성화
→ 일부 출력값이 확률적으로 0
```

추론 중:

```text
Dropout 비활성화
→ 전체 뉴런 사용
```

일반적으로:

```python
model.fit(...)
```

에서는 Dropout이 활성화되고,

```python
model.predict(...)
model.evaluate(...)
```

에서는 Dropout이 비활성화된다.

---

# 13. Functional Branch와 Dropout의 차이

## Functional 모델의 Branch

```text
여러 경로를 의도적으로 만든다.
```

예:

```text
              ┌→ Branch A ─┐
Input ────────┤             ├→ Merge
              └→ Branch B ─┘
```

두 Branch는 학습 중 계속 존재한다.

## Dropout

```text
이미 존재하는 경로 중 일부를
학습할 때마다 확률적으로 비활성화한다.
```

예:

```text
이번 Batch

h1 → ON
h2 → OFF
h3 → ON

다음 Batch

h1 → OFF
h2 → ON
h3 → ON
```

정리:

```text
Functional 모델의 Branch
= 여러 경로를 설계

Dropout
= 기존 경로 일부를 랜덤하게 끄기
```

---

# 14. Branch 모델과 앙상블

Branch 모델:

```text
              ┌→ Branch A ─┐
Input ────────┤             ├→ Merge → Output
              └→ Branch B ─┘
```

독립 앙상블:

```text
Model A ─┐
Model B ─┼→ 평균 / 투표 → 최종 예측
Model C ─┘
```

겉으로는 여러 경로의 결과를 합친다는 점에서 비슷해 보인다.

하지만 학습 방식에는 중요한 차이가 있다.

---

# 15. 독립 앙상블

앙상블에서는 각 모델을 보통 독립적으로 학습한다.

```text
Model A → y_hat_A → Loss_A
Model B → y_hat_B → Loss_B
Model C → y_hat_C → Loss_C
```

각 모델은 자신의 Loss를 보고 자신의 가중치를 업데이트한다.

```text
Loss_A → Model A의 W 업데이트
Loss_B → Model B의 W 업데이트
Loss_C → Model C의 W 업데이트
```

즉 Model A는 Model B가 어떤 값을 예측하는지 알 필요가 없다.

각 모델은 자기 예측을 잘 맞히는 방향으로 학습한다.

학습이 끝난 뒤 결과를 합친다.

```text
Model A ─┐
Model B ─┼→ 평균 / 투표 / Stacking
Model C ─┘
```

---

# 16. Branch 모델은 최종 Loss를 통해 공동 학습한다

하나의 최종 출력으로 합치는 Branch 모델을 생각해보자.

```text
Branch A ─┐
          ├→ Merge → 최종 예측 → Loss
Branch B ─┘
```

각 Branch는 서로 다른 가중치를 가진다.

```text
Branch A → W_A
Branch B → W_B
```

하지만 최종 Loss가 역전파되면서 두 Branch의 가중치가 모두 업데이트된다.

```text
              Loss
               ↓
             역전파
           ↙       ↘
     Branch A     Branch B
       W_A          W_B
```

즉:

> **가중치를 직접 공유하는 것이 아니라 하나의 최종 목적함수를 기준으로 함께 최적화된다.**

이런 방식을 Joint Training이라고 볼 수 있다.

---

# 17. Branch는 서로 보완하는 표현을 학습할 수 있다

예를 들어 정답이:

```text
y = 10
```

이고 두 Branch의 예측값을 평균한다고 하자.

```text
Branch A = 8
Branch B = 12
```

평균:

```text
(8 + 12) / 2 = 10
```

따라서:

```text
Branch A = 8  ─┐
               ├→ 평균 = 10 → Loss ≈ 0
Branch B = 12 ─┘
```

이 될 수 있다.

이 경우 Branch A와 Branch B 각각은 정답과 다르지만 최종 조합은 정답을 맞힌다.

즉 이 구조에서는:

```text
A 혼자 정답을 맞혀야 한다.
B 혼자 정답을 맞혀야 한다.
```

가 아니라

```text
A와 B를 합친 최종 결과가 정답에 가까우면 된다.
```

라는 방향으로 학습될 수 있다.

단, 모든 Branch 모델이 Branch별 예측값을 직접 평균하는 것은 아니다.

실제로는 중간 feature를 합친 뒤 Dense 레이어에서 최종 예측을 만드는 경우도 많다.

---

# 18. 독립 앙상블은 각 모델이 따로 정답을 학습한다

같은 예를 독립 앙상블에서 보면:

```text
정답 = 10

Model A = 8
Model B = 12
```

각 모델은 자신의 Loss를 따로 계산한다.

```text
Model A
8 → 정답 10과 비교 → Loss_A

Model B
12 → 정답 10과 비교 → Loss_B
```

따라서 두 모델 모두 각각 `10`에 가까워지도록 학습한다.

즉:

> **앙상블은 각자가 잘한 뒤 합친다.**

---

# 19. Branch 모델은 함께 잘하도록 학습한다

Branch 모델에서는 처음부터 최종 출력의 Loss가 여러 Branch로 역전파된다.

```text
Branch A ─┐
          ├→ 최종 예측 → Loss
Branch B ─┘
```

따라서:

> **Branch 모델은 처음부터 최종 조합이 잘 작동하도록 함께 학습한다.**

라고 이해할 수 있다.

---

# 20. 수식으로 보는 차이

## 독립 앙상블

```text
Loss_A = L(y, y_hat_A)

Loss_B = L(y, y_hat_B)
```

각 모델은 자신의 Loss를 최소화한다.

---

## 평균 Merge를 사용하는 Branch 모델

```text
y_hat
= (y_hat_A + y_hat_B) / 2
```

최종 Loss:

```text
Loss
= L(y, (y_hat_A + y_hat_B) / 2)
```

이 경우 각 Branch의 개별 예측보다는 **결합된 최종 예측**이 직접적인 최적화 대상이다.

---

# 21. Weight Sharing과 Joint Training은 다르다

Branch 모델에서:

```text
Branch A → W_A
Branch B → W_B
```

라면 일반적으로 `W_A`와 `W_B`는 서로 다른 가중치다.

따라서:

```text
Branch A의 W가 Branch B로 전달된다.
```

는 뜻이 아니다.

정확한 표현:

```text
Joint Training
= 같은 최종 목적함수를 기준으로 함께 최적화
```

반면:

```text
Weight Sharing
= 실제로 같은 가중치 tensor를 여러 위치나 경로에서 재사용
```

이다.

둘은 다른 개념이다.

---

# 22. 앙상블과 Branch 모델의 비유

## 앙상블

학생 여러 명이 각자 따로 공부한다.

```text
학생 A → 혼자 공부
학생 B → 혼자 공부
학생 C → 혼자 공부
```

각자 시험을 본 뒤 마지막에 답을 모은다.

```text
A의 답
B의 답
C의 답
   ↓
평균 / 투표
```

---

## Branch 모델

학생 여러 명이 처음부터 하나의 팀 답안을 만든다고 생각할 수 있다.

```text
학생 A ─┐
학생 B ─┼→ 하나의 공동 답안
학생 C ─┘
```

최종 평가는 공동 답안을 기준으로 이루어진다.

따라서 각 Branch의 표현이 최종 결과에 함께 영향을 줄 수 있다.

---

# 23. 왜 두 방식의 성능이 다를 수 있는가?

## 독립 앙상블

```text
각 모델이 따로 학습
→ 서로 다른 초기값/구조/데이터 사용 가능
→ 서로 다른 실수 발생 가능
→ 평균/투표로 일부 실수 상쇄
```

앙상블에서는 모델 간 다양성이 중요하다.

---

## Branch 모델

```text
하나의 모델 내부
→ 여러 Branch
→ 같은 최종 Loss
→ 함께 최적화
```

서로 보완적인 표현을 학습할 수도 있지만, 비슷한 표현을 학습할 수도 있다.

따라서:

```text
Branch가 많다
= 무조건 성능이 좋아진다
```

는 아니다.

---

# 24. 세 개념 비교

| 구분 | Functional 모델의 Branch | Dropout | 독립 앙상블 |
|---|---|---|---|
| 목적 | 복잡한 구조 설계, 여러 표현 결합 | 과적합 완화 | 일반화 성능·안정성 향상 |
| 경로 | 여러 경로를 명시적으로 생성 | 기존 출력 일부를 확률적으로 0 처리 | 모델 자체를 여러 개 생성 |
| 학습 | 하나의 계산 그래프 안에서 공동 학습 | 랜덤 mask 적용 | 모델별 독립 학습 |
| Loss | 구조에 따라 하나 또는 여러 개 가능 | 원래 모델의 Loss | 모델마다 개별 Loss |
| 가중치 | Branch별로 보통 별도 | 가중치 삭제 안 됨 | 모델마다 별도 |
| 결과 결합 | 모델 내부 Merge | 별도 결합 없음 | 평균/투표/Stacking 등 |
| 추론 | 모든 Branch 사용 | Dropout OFF | 여러 모델 예측 결합 |

# 25. 최종 핵심 정리

```text
Sequential
= 레이어를 일렬로 쌓는 방식

Functional 모델
= Input과 Model을 사용해 연결 구조를 직접 설계한 모델

Branch
= 하나의 모델 안에 여러 경로를 만드는 것

Dropout
= 학습 중 각 뉴런의 출력값을 일정 확률로 0으로 만드는 것

Dropout(0.5)
= 각 출력이 50% 확률로 0
≠ 매번 정확히 절반을 골라서 OFF

독립 앙상블
= 여러 모델을 따로 학습한 뒤 결과를 결합

Branch 모델
= 여러 Branch가 최종 목적함수를 통해 함께 최적화
```

가장 중요한 문장:

> **Functional 모델은 복잡한 연결 구조를 표현할 수 있는 모델 형태다.**

> **Dropout은 W를 삭제하지 않는다. 각 뉴런의 출력값을 `rate` 확률로 0으로 만든다.**

> **`Dropout(0.5)`는 매번 정확히 절반이 꺼지는 것이 아니라 각 출력이 50% 확률로 꺼지는 것이다.**

> **독립 앙상블은 각 모델을 따로 학습한 뒤 합친다.**

> **Branch 모델은 하나의 계산 그래프 안에서 최종 Loss를 통해 여러 Branch가 함께 최적화된다.**

한 문장으로 줄이면:

> **앙상블은 "각자 학습한 뒤 합치기", Branch 모델은 "하나의 모델 안에서 함께 최적화하기", Dropout은 "학습 중 각 출력을 확률적으로 끄기"이다.**
