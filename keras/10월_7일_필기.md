# Keras Layer별 입력 / 출력 차원 정리

## 1. 전체 요약

| 항목 | Dense | Conv2D | Conv1D | RNN / `return_sequences` | Embedding |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **입력** | 2차원 이상 | 4차원 | 3차원 | 3차원 | 2차원 |
| **출력** | 2차원 이상 | 4차원 | 3차원 | 2차원 / 3차원 | 3차원 |
| **`input_shape`** | 1차원 이상 | 3차원 | 2차원 | 2차원 | 보통 직접 지정하지 않음 |
| **Flatten** | △ | O | O | X / O | X |

> `input_shape`는 **실제 X의 shape에서 batch 축을 제외한 나머지**를 의미한다.

예를 들어:

```python
x.shape = (1000, 144, 13)
```

이라면

```text
1000 = batch
144  = timestep
13   = feature
```

이므로:

```python
input_shape=(144, 13)
```

가 된다.

즉,

```text
X의 차원 수 - 1 = input_shape의 차원 수
```

이라고 생각하면 된다.

# 2. Dense

Dense는 일반적으로 2차원 입력을 많이 사용하지만 **2차원 이상이면 입력 가능**하다.

가장 중요한 특징은:

> Dense는 **마지막 축(last axis)** 에 대해서 연산한다.

## 2차원 입력

```python
x.shape = (100, 8)

model.add(Dense(32, input_shape=(8,)))
```

Shape 변화:

```text
(batch, feature)
(100, 8)

↓ Dense(32)

(100, 32)
```

마지막 축:

```text
8 → 32
```

로 변한다.

---

## 3차원 입력

```python
x.shape = (100, 20, 8)

model.add(Dense(32, input_shape=(20, 8)))
```

Shape:

```text
(100, 20, 8)

↓ Dense(32)

(100, 20, 32)
```

Dense는 `20`개의 timestep을 서로 연결해서 처리하는 것이 아니라,

```text
t1의 feature 8개 → Dense → 32개
t2의 feature 8개 → Dense → 32개
t3의 feature 8개 → Dense → 32개
...
```

처럼 **각 위치에서 마지막 축만 처리한다.**

따라서:

```text
Dense(3차원 입력 가능)
≠
RNN
```

이다.

---

## 4차원도 가능

```text
(N, 28, 28, 64)

↓ Dense(32)

(N, 28, 28, 32)
```

역시 마지막 축만:

```text
64 → 32
```

로 바뀐다.

---

# 3. Flatten을 사용하는 이유

Dense는 마지막 축만 처리한다.

예를 들어 CNN의 출력이:

```text
(N, 7, 7, 64)
```

일 때 바로:

```python
Dense(10)
```

을 연결하면:

```text
(N, 7, 7, 64)

↓ Dense(10)

(N, 7, 7, 10)
```

이 된다.

Dense가 `7 × 7 × 64` 전체를 한 번에 처리하는 것이 아니라,  
각 `7 × 7` 위치마다 마지막 `64`개 feature만 처리한다.

전체 값을 하나의 feature 벡터로 만들어 Dense에 넣고 싶다면:

```python
Flatten()
Dense(10)
```

을 사용한다.

```text
(N, 7, 7, 64)

↓ Flatten

(N, 3136)

↓ Dense(10)

(N, 10)
```

즉 Flatten은:

> 여러 축에 흩어진 데이터를 하나의 feature 축으로 펴서 Dense가 전체 값을 같이 사용할 수 있도록 만든다.

# 4. Conv2D

Conv2D는 주로 이미지에 사용한다.

입력 형태:

```text
(batch, height, width, channel)
```

예:

```text
(60000, 28, 28, 1)
```

MNIST 흑백 이미지라면:

```text
60000 = 이미지 수
28    = height
28    = width
1     = channel
```

이다.

모델:

```python
model.add(
    Conv2D(
        filters=64,
        kernel_size=(3, 3),
        input_shape=(28, 28, 1)
    )
)
```

Shape 변화:

```text
(N, 28, 28, 1)

↓ Conv2D(filters=64, kernel_size=3)

(N, 26, 26, 64)
```

여기서:

```text
64 = filter 개수
   = 출력 channel 개수
   = 생성된 feature map 개수
```

이다.

### 중요한 점

숫자 `7` 이미지 하나를 넣고 `filters=64`를 사용한다고 해서  
`7` 이미지가 64장 복제되는 것은 아니다.

```text
숫자 7 이미지

↓ 여러 Filter

세로선에 반응하는 특징
가로선에 반응하는 특징
대각선에 반응하는 특징
모서리에 반응하는 특징
기타 학습된 특징
...
```

처럼 **같은 이미지에서 서로 다른 특징을 추출한 feature map**이 만들어진다.

---

# 5. Conv1D

Conv1D는 주로 시계열이나 sequence 데이터에 사용한다.

입력:

```text
(batch, timestep, feature)
```

예:

```text
(N, 144, 13)
```

의미:

```text
N   = sample
144 = timestep
13  = feature
```

모델:

```python
model.add(
    Conv1D(
        filters=64,
        kernel_size=3,
        input_shape=(144, 13)
    )
)
```

`padding='valid'`라면:

```text
(N, 144, 13)

↓ Conv1D(filters=64, kernel_size=3)

(N, 142, 64)
```

여기서 Conv1D의 kernel은 timestep 축을 따라 이동한다.

```text
t1 t2 t3
↓ kernel

   t2 t3 t4
   ↓ kernel

      t3 t4 t5
      ↓
      ...
```

즉:

> Conv1D는 가까운 timestep들의 **국소적인 패턴(local pattern)** 을 추출한다.

그리고:

```text
filters=64
```

라면 출력 feature는 64개가 된다.

이 64개는 기존의 원래 feature가 아니라 CNN이 학습한 새로운 feature이다.

```text
원본

(N, 144, 13)

↓ Conv1D

(N, 142, 64)

64 = CNN이 새롭게 추출한 특징들
```

---

# 6. RNN / SimpleRNN / LSTM / GRU

RNN 계열의 입력 역시:

```text
(batch, timestep, feature)
```

형태의 3차원이다.

예:

```python
model.add(
    SimpleRNN(
        units=10,
        input_shape=(144, 13)
    )
)
```

입력:

```text
(N, 144, 13)
```

RNN은 timestep을 순서대로 처리한다.

```text
t1의 feature
↓
hidden state h1

t2의 feature + h1
↓
hidden state h2

t3의 feature + h2
↓
hidden state h3

...
```

따라서 Conv1D와 RNN은 둘 다 3차원 입력을 사용하지만 역할이 다르다.

```text
Conv1D
→ 가까운 timestep의 국소 패턴 추출

RNN
→ timestep의 순서와 이전 hidden state를 고려
```

---

# 7. `return_sequences=False`

RNN의 기본값이다.

```python
model.add(SimpleRNN(10))
```

입력:

```text
(N, T, F)
```

출력:

```text
(N, 10)
```

즉:

```text
3차원

(N, timestep, feature)

↓

RNN

↓

2차원

(N, units)
```

이 된다.

따라서 바로 Dense와 연결할 수 있다.

```python
model.add(SimpleRNN(10, input_shape=(144, 13)))
model.add(Dense(1))
```

Shape:

```text
(N, 144, 13)

↓ SimpleRNN(10)

(N, 10)

↓ Dense(1)

(N, 1)
```

이미 RNN이 2차원으로 출력했기 때문에 Flatten이 필요 없다.

---

# 8. `return_sequences=True`

```python
model.add(
    SimpleRNN(
        10,
        return_sequences=True
    )
)
```

이면 모든 timestep의 출력을 유지한다.

```text
(N, T, F)

↓ RNN(10, return_sequences=True)

(N, T, 10)
```

즉 3차원으로 출력된다.

이 상태에서 Flatten을 사용할 수도 있다.

```text
(N, T, 10)

↓ Flatten

(N, T × 10)

↓ Dense

(N, output)
```

하지만 다음에 RNN을 또 연결할 것이라면 Flatten을 사용하면 안 된다.

```python
model.add(SimpleRNN(10, return_sequences=True))
model.add(SimpleRNN(20))
model.add(Dense(1))
```

Shape:

```text
(N, T, F)

↓ RNN(10, return_sequences=True)

(N, T, 10)

↓ RNN(20)

(N, 20)

↓ Dense(1)

(N, 1)
```

따라서:

```text
return_sequences=False
→ 2차원 출력
→ Flatten 불필요

return_sequences=True
→ 3차원 출력
→ 필요하면 Flatten 가능

return_sequences=True + 다음 RNN
→ Flatten 사용 X
```

# 9. Conv1D → RNN

Conv1D 출력과 RNN 입력은 둘 다 3차원이므로 바로 연결할 수 있다.

```python
model = Sequential()

model.add(
    Conv1D(
        filters=64,
        kernel_size=3,
        input_shape=(144, 13)
    )
)

model.add(SimpleRNN(32))

model.add(Dense(1))
```

Shape:

```text
(N, 144, 13)

↓ Conv1D(filters=64)

(N, 142, 64)

↓ SimpleRNN(32)

(N, 32)

↓ Dense(1)

(N, 1)
```

역할은:

```text
Conv1D
→ 가까운 timestep의 패턴을 추출

RNN
→ 추출된 패턴이 시간에 따라 어떻게 이어지는지 처리

Dense
→ 최종 예측
```

으로 나눌 수 있다.

---

# 10. Conv2D → RNN

Conv2D의 출력은 4차원이다.

```text
(N, H, W, C)
```

RNN은 3차원을 요구한다.

```text
(N, timestep, feature)
```

따라서 바로 연결할 수 없고 `Reshape`가 필요하다.

예:

```text
(N, 24, 24, 16)

↓ Reshape

(N, 24×24, 16)

↓ SimpleRNN

(N, units)
```

예제:

```python
model.add(Conv2D(16, (3, 3)))

model.add(
    Reshape(
        target_shape=(24 * 24, 16)
    )
)

model.add(SimpleRNN(10))
```

# 11. Embedding

Embedding은 Token ID를 학습 가능한 벡터로 변환한다.

입력은 보통:

```text
(batch, sequence_length)
```

2차원이다.

예:

```text
(N, 5)

[0, 0, 4, 7, 2]
```

Embedding:

```python
model.add(
    Embedding(
        input_dim=30,
        output_dim=10
    )
)
```

각 Token ID 하나를 10차원 벡터로 변환한다.

```text
Token ID 7

↓

[0.12, -0.53, 0.21, ..., 0.77]
```

따라서 Shape은:

```text
(N, 5)

↓ Embedding(30, 10)

(N, 5, 10)
```

즉:

```text
2차원 → Embedding → 3차원
```

이다.

이 결과는 바로 RNN 계열에 넣을 수 있다.

```python
model.add(Embedding(30, 10))
model.add(SimpleRNN(32))
model.add(Dense(1))
```

Shape:

```text
(N, 5)

↓ Embedding

(N, 5, 10)

↓ SimpleRNN(32)

(N, 32)

↓ Dense(1)

(N, 1)
```

여기서 RNN 입장에서는:

```text
5  = timestep
10 = feature
```

가 된다.

# 12. Flatten 사용 정리

`O`, `△`, `X`는 절대적인 사용 가능 여부가 아니라 **일반적인 사용 패턴**을 의미한다.

```text
O = 자주 사용
△ = 상황에 따라 사용
X = 보통 불필요
```

## Dense — △

Dense는 고차원 입력도 받을 수 있기 때문에 Flatten이 필수는 아니다.

하지만 여러 축을 하나로 합쳐 전체를 하나의 feature vector로 만들고 싶다면 사용한다.

---

## Conv2D — O

CNN 출력:

```text
(N, H, W, C)
```

를 최종 Dense 분류기에 넣을 때:

```text
Conv2D

↓

Flatten

↓

Dense
```

형태를 자주 사용한다.

단,

```python
GlobalAveragePooling2D()
```

로 대체할 수도 있다.

---

## Conv1D — O

출력:

```text
(N, timestep, filters)
```

을:

```text
Flatten
↓
Dense
```

로 연결할 수 있다.

역시:

```python
GlobalAveragePooling1D()
```

등으로 대체할 수 있다.

---

## RNN — X / O

### `return_sequences=False`

```text
(N,T,F)
↓
(N,units)
```

이미 2차원이므로 Flatten이 불필요하다.

### `return_sequences=True`

```text
(N,T,F)
↓
(N,T,units)
```

3차원이므로 필요하다면 Flatten할 수 있다.

하지만 다음 레이어가 또 RNN이라면 Flatten하면 안 된다.

---

## Embedding — X

Embedding은:

```text
(N,T)

↓

(N,T,E)
```

로 만들어 RNN, LSTM, GRU, Conv1D 등에 넘기기 위한 경우가 많다.

따라서 일반적으로:

```text
Embedding
↓
RNN / LSTM / GRU / Conv1D
```

형태로 사용한다.

기술적으로 Flatten을 사용하는 것도 가능하지만, timestep 구조가 사라진다.

---

# 핵심 Shape 암기

```text
Dense

(..., feature)
↓
(..., units)
```

```text
Conv1D

(batch, timestep, feature)
↓
(batch, new_timestep, filters)
```

```text
Conv2D

(batch, height, width, channel)
↓
(batch, new_height, new_width, filters)
```

```text
RNN
return_sequences=False

(batch, timestep, feature)
↓
(batch, units)
```

```text
RNN
return_sequences=True

(batch, timestep, feature)
↓
(batch, timestep, units)
```

```text
Embedding

(batch, timestep)
↓
(batch, timestep, embedding_dim)
```

## 최종 핵심

> **레이어를 서로 연결할 수 있는지는 앞 레이어의 출력 Shape과 다음 레이어가 요구하는 입력 Shape을 확인하면 된다.**

그리고:

> **Dense는 마지막 축을 처리하고, Conv는 주변 영역의 패턴을 찾으며, RNN은 timestep의 순서를 처리한다.**

**피클(pickle)**은 보통 Python 객체를 파일로 저장했다가 다시 불러오는 직렬화 방식이다. FAISS 예제에서 저장된 문서 저장소를 로드할 때 피클 파일이 쓰일 수 있으므로, 신뢰할 수 있는 출처의 파일만 역직렬화해야 한다.

# 13. Shape를 계산할 때 추가로 기억할 점

## batch 축과 `input_shape`

실제 입력 텐서의 첫 번째 축은 보통 batch다. 따라서 모델에 지정하는 `input_shape`에서는 그 축을 뺀다.

```text
실제 X.shape             (100, 144, 13)
모델이 받는 전체 모양    (None, 144, 13)
input_shape              (144, 13)
```

`None`은 batch 크기가 실행 시 달라질 수 있다는 뜻이다. `input_shape`는 batch 크기를 정하는 옵션이 아니다.

## Dense는 바깥 축을 보존하고 마지막 축에 같은 변환을 적용

Dense에 `(N, T, F)`를 넣으면 출력은 `(N, T, units)`다. 각 batch와 timestep 위치마다 마지막 축 `F`에 같은 Dense 가중치를 적용한다. timestep들을 서로 섞지는 않는다.

```text
(N, 20, 8) → Dense(32) → (N, 20, 32)
```

따라서 timestep 간 순서나 관계를 학습해야 한다면 RNN, Conv1D 또는 다른 sequence 처리 레이어가 필요하다.

## Conv 출력 길이 계산

앞의 Conv1D·Conv2D 출력 예시는 `padding="valid"`, `strides=1`, `dilation_rate=1`을 가정한다. 한 축의 출력 크기는 다음처럼 계산한다.

```text
effective_kernel = dilation_rate × (kernel_size - 1) + 1

padding="valid": floor((input_size - effective_kernel) / stride) + 1
padding="same":  ceil(input_size / stride)
```

Conv2D는 이 계산을 높이와 너비에 각각 적용한다. 기본 `channels_last` 형식에서는 입력이 `(N, H, W, C)`이고, 출력 마지막 축은 `filters`가 된다. 예를 들어 `(N, 28, 28, 1)`에 `Conv2D(64, 3)`을 적용하면 `valid`일 때 `(N, 26, 26, 64)`, stride 1의 `same`일 때 `(N, 28, 28, 64)`다.

## Flatten과 Global Pooling 선택

Flatten은 공간·시간 위치를 모두 이어 붙이므로 위치별 값은 보존하지만 Dense의 입력 크기와 파라미터 수가 커질 수 있다. Global Average Pooling은 위치 축을 평균 내어 feature/channel 축만 남긴다.

```text
(N, 7, 7, 64) → Flatten()               → (N, 3136)
(N, 7, 7, 64) → GlobalAveragePooling2D() → (N, 64)
```

예를 들어 Flatten 뒤 `Dense(128)`을 연결하면 Dense 가중치만 `3136 × 128`개 필요하다. 메모리와 과적합을 줄이고 싶을 때 Global Pooling을 고려할 수 있다.

## RNN의 timestep 축

`return_sequences=False`는 마지막 timestep의 출력만 반환해 `(N, units)`를 만든다. `return_sequences=True`는 timestep별 출력을 모두 남겨 `(N, T, units)`를 만든다. 따라서 RNN을 연속으로 쌓을 때 중간 RNN은 보통 `return_sequences=True`여야 다음 RNN에 timestep 축을 전달할 수 있다.

```text
(N, T, F)
→ SimpleRNN(10, return_sequences=True) → (N, T, 10)
→ SimpleRNN(20)                        → (N, 20)
```

## Conv2D 출력에서 RNN으로 갈 때

`Reshape`는 원소 수를 바꾸지 않고 축의 해석만 바꾼다. 따라서 예제의 `(N, 24, 24, 16) → (N, 24 × 24, 16)`은 실제 Conv2D 출력의 높이와 너비가 각각 24일 때만 맞는다.

```text
입력 (N, 26, 26, 1)
→ Conv2D(16, 3, padding="valid")  (N, 24, 24, 16)
→ Reshape((24 × 24, 16))          (N, 576, 16)
→ RNN                              (N, units)
```

입력 크기나 padding을 바꾸면 Reshape의 target도 함께 계산해서 바꿔야 한다.

## Embedding 입력 범위와 padding

`Embedding(input_dim, output_dim)`에서 `input_dim`은 사용할 Token ID의 범위 크기이고, ID는 `0`부터 `input_dim - 1`까지여야 한다. `output_dim`은 Token 하나를 나타내는 벡터 길이다.

```text
Embedding(input_dim=30, output_dim=10)
Token ID 입력: (N, T)
출력:          (N, T, 10)
```

0을 padding 전용 ID로 쓴다면 `mask_zero=True`를 고려할 수 있다. 이때 0은 실제 단어 ID로 함께 사용하지 않아야 하며, 뒤쪽 레이어가 전달된 mask를 지원해야 한다.

## Shape 오류를 추적하는 순서

1. `X.shape`를 출력하고 첫 축이 batch인지 확인한다.
2. 각 레이어의 출력 shape를 한 단계씩 적는다.
3. Dense는 마지막 축, Conv는 kernel·stride·padding·filters, RNN은 timestep 축과 `return_sequences`를 확인한다.
4. Reshape를 썼다면 앞뒤의 원소 수가 같은지 계산한다.
5. `model.summary()`에서 레이어별 출력 shape와 파라미터 수를 확인한다.

```python
print(X.shape)
model.summary()
```

`model.summary()`에 `(None, 144, 13)`처럼 표시된 `None`은 batch 크기가 정해지지 않았다는 뜻이다.

# 14. RAG 코드 수정 내용 분석

이 절은 이번에 함께 검토하고 수정한 `RAG` 폴더의 코드 흐름을 기록한다. 기존 Keras Shape 필기와 구분하기 위해 별도 절로 추가했다.

## RAG 전체 데이터 흐름

```text
원문 파일
  ↓ TextLoader / glob
Document(page_content, metadata)
  ↓ TextSplitter
Chunk(Document)
  ↓ 임베딩 모델
각 Chunk의 벡터
  ↓ Chroma 또는 FAISS에 저장
질문을 같은 임베딩 모델로 벡터화
  ↓ 유사도 검색
관련 Chunk
  ↓ 프롬프트에 컨텍스트로 전달
LLM 답변
```

벡터 저장소는 벡터만 보관하는 것이 아니다. 검색 결과를 답변 근거로 사용하려면 청크 원문과 출처 metadata도 함께 보존해야 한다.

## Chroma 저장·불러오기

### `rag11_Chroma_save.py`

삼성전자와 엔비디아 텍스트 파일을 각각 읽고, `chunk_size=300`, `chunk_overlap=100`으로 나눈 뒤 Chroma의 `croma11` 컬렉션에 저장한다. 실행 때마다 청크의 출처·순번·본문으로 SHA-256 ID를 만들어 같은 입력을 다시 실행해도 같은 레코드 ID를 사용하게 했다.

### `rag11_Chroma02_load.py`

원문 파일을 다시 읽거나 임베딩해 저장하지 않는다. 저장할 때와 같은 임베딩 모델, Chroma 저장 위치, 컬렉션 이름으로 기존 DB를 열고 `similarity_search()`로 질문과 가까운 문서 2개를 가져온다.

### `rag12_Chroma03_save.py`

폴더의 `.txt` 파일을 `glob`으로 모으고, 파일명을 정렬해 처리 순서를 일정하게 했다. 모든 텍스트를 `Document`로 읽은 뒤 `chunk_size=300`, `chunk_overlap=10`으로 분할하고 Chroma의 `croma12` 컬렉션에 저장한다. 저장 청크에는 출처·순번·본문 기반의 고정 ID를 부여한다.

### `rag12_Chroma04_load.py`

기존 `croma12` 컬렉션을 열어 검색하는 코드다. `rag12_Chroma03_save.py`가 저장한 DB 경로와 컬렉션 이름, 임베딩 모델이 서로 맞아야 검색 벡터와 저장 벡터를 비교할 수 있다.

## 검색에서 답변까지

### `rag13_Chroma_pipeline1.py`

기존 Chroma DB에서 상위 2개 청크를 검색하고, 결과가 임계값보다 낮으면 모델을 호출하지 않고 정해 둔 거절 문구를 출력한다. 검색 결과가 있으면 예전처럼 첫 문서만 사용하는 대신 **검색된 문서 전체**를 컨텍스트에 넣어 답변한다.

### `rag14_Chroma_pipeline2.py`

`create_retrieval_chain`으로 `검색기 → 문서 결합 체인 → 모델`을 연결한다. 프롬프트를 system과 human 메시지로 나누고, 검색 컨텍스트 안에 답의 근거가 없을 때 고정 문구를 내도록 규칙을 명시했다.

### `rag15_Chroma_gradio.py`

Chroma 검색과 답변 생성을 Gradio 채팅 화면에 연결한다. 후속 질문의 검색어에 직전 사용자 질문을 더해 “그 회사” 같은 표현이 어느 회사를 가리키는지 보완한다. 검색 결과가 없으면 답변 모델을 부르지 않고 바로 거절 문구를 반환하며, 최근 대화 기록은 지시 대상을 파악하는 용도로 프롬프트에 전달한다.

## FAISS 저장·챗봇

### `rag17_FAISS_1_save.py`

삼성전자·엔비디아 문서를 청킹하고 `FAISS.from_documents()`로 임베딩과 인덱스를 만든 뒤 `save_local()`로 저장한다. 사용하지 않던 직접 인덱스 초기화 코드를 제거했다. 그 코드는 실제 저장에 연결되지 않았고, 차원 확인용 임베딩 요청까지 추가로 발생시켰기 때문이다.

### `rag17_FAISS_2_load copy.py`

저장된 FAISS 인덱스와 문서 저장소만 불러와 검색한다. 원문 로드, 청킹, 새 인덱스 생성은 하지 않는다. `FAISS.load_local()`에는 임베딩 객체 인자명 `embeddings`를 사용한다.

### `rag18_FAISS_gradio_맹글.py`

저장된 FAISS DB를 불러와 Gradio RAG 챗봇을 실행한다. 검색 문서가 없으면 모델 호출 없이 고정 거절 문구를 반환한다. 검색어에는 직전 사용자 질문을 붙여 후속 질문을 보완하고, 답변 아래 검색 문서의 파일명을 출처로 표시한다. Gradio의 메시지 형식과 구형 사용자·챗봇 튜플 형식을 모두 대화 기록으로 처리한다.

## 공통 수정과 주의사항

- API 키를 바로 `.strip()`하지 않고 먼저 존재 여부를 검사한다. 키가 없거나 공백뿐이면 원인을 알 수 있는 오류를 낸다.
- Chroma 저장 코드에서 고정 문서 ID를 사용해 같은 청크의 재실행 저장이 중복 레코드를 만들지 않도록 했다. 기존 DB에 이미 들어간 과거 중복 데이터까지 자동 삭제하는 동작은 추가하지 않았다.
- 검색 점수 임계값 `0.05`는 시작 설정이다. 임베딩 모델, 거리 설정, 문서 내용이 달라지면 관련 질문과 무관 질문의 점수를 확인해 조정해야 한다.
- 프롬프트는 모델이 컨텍스트를 따르도록 지시하지만, 프롬프트만으로 환각을 완전히 막을 수는 없다. 검색 품질과 임계값도 함께 점검해야 한다.
- FAISS의 `allow_dangerous_deserialization=True`는 저장 파일을 피클 방식으로 읽을 수 있게 한다. 직접 생성했거나 신뢰하는 로컬 파일에만 사용해야 한다.
- 이번 보완에서는 각 프로젝트의 데이터·DB 경로 문자열은 바꾸지 않았다. 상대 경로는 실행 당시 현재 작업 폴더를 기준으로 해석된다는 점을 별도로 확인해야 한다.
